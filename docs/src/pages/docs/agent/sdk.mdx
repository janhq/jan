# Agent SDK (Preview)

Want Jan Agent inside your own application - a script, a service, a robot controller - instead of
in a terminal? You start `jan cli agent run` as a child process and talk to it over **`stream-json`**:
one JSON record per line on stdout, one message per line on stdin. Your code sees every token, tool
call and permission prompt, and can hand the agent **host tools**: tools your code executes.

<Callout type="warning">
The Agent SDK is a preview. It ships with Jan Agent in the `agent-nightly` channel, not in stable
releases - expect nightly-quality builds. There is no SDK package to install yet: the recipes here
drive the `jan` binary with nothing but Node.js or Python and their standard libraries.
</Callout>

## How one run works

```text
   your app                                   jan cli agent run
   | spawn --output-format stream-json        |
   |       --input-format stream-json         |
   | <------------------------------ init --- |  session, model, tools, caps
   | <------------- token, tool_call, ... --- |  the run, as it happens
   | <---------------------- tool_request --- |  the model called your host tool
   | ---- tool_result ----------------------> |
   | <---------------- permission_request --- |  only when the run asks (--safe)
   | ---- permission -----------------------> |
   | <---------------------------- result --- |  answer, stop reason, usage; the process exits
```

One process runs one task. Follow-up messages on stdin join the same run, and `--resume` continues
a saved session in a new process.

## What your build supports

Check the build you run rather than trusting a page: the `init` record says what this run accepts.

| Capability | How to tell | Nightly `0.8.4-49` (published 2026-09-22) |
| --- | --- | --- |
| Streamed events and a terminal `result` | `init.protocol_version` is `1` | Yes |
| Follow-ups, permission answers, `abort` | `init.input_kinds` lists `user`, `permission` and `abort` | Yes |
| [Host tools](/docs/agent/sdk-tools) | `jan cli agent run --help` lists `--host-tools`; `init.input_kinds` lists `tool_result` | No - on `main`, arriving with the next nightly |
| The generated JSON Schema | `jan cli agent schema` exists | No - on `main`, arriving with the next nightly |
| Several sessions in one process over JSON-RPC | `jan cli agent --help` lists `rpc` | No - on `main`, arriving with the next nightly. It has no host tools yet |
| Images in a `user` message | `init.input_content_parts` is not `null` | No. Builds from `main` accept and validate them but **do not forward them to the model yet**: only the text parts reach the provider |

Not in any build yet: images in a host tool result, host tools called from subagents, and the
JavaScript and Python SDK packages. Run `jan update` to move to the newest nightly.
