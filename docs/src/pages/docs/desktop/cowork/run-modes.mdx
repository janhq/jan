# Run Modes

The mode picker sits next to the input. It decides how much the agent can do without asking.

| Mode | Behaviour |
|---|---|
| **Normal** | Prompts before risky tool calls |
| **Plan** | Read-only — write/edit/exec tools are denied |
| **Bypass permissions** | Auto-allow every tool call — no prompts |

The mode is per session, so one session can be planning while another builds.

## Normal

The default, and the right choice most of the time.

Reading, searching, and listing files happen without interruption. Anything that changes your
machine stops and asks:

- **write / edit** — you see the diff before approving
- **bash** — you see the exact command

Approving one command doesn't approve the next. The agent can chew through the read-only work on its
own and only interrupt you when it matters.

## Plan

Write, edit, and exec tools are **denied**, not queued. The agent can read your project, search the
web, and think — then tell you what it would do.

Use it when:

- You're pointing the agent at unfamiliar code and want an assessment before any changes
- The task is ambiguous and you'd rather agree on an approach first
- You want a second opinion on a change without risking one

When you like the plan, switch to Normal and tell it to go ahead. The conversation carries over.

## Bypass permissions

Every tool call is auto-approved. No diffs, no prompts, no sandbox.

This is genuinely faster for long mechanical jobs — a rename across fifty files, a migration where
you already know the shape of every edit. It is also the mode with nothing standing between the
agent and your disk.

<Callout type="warning">
  Bypass permissions turns off the sandbox as well as the prompts. Use it on a clean git branch you
  can reset, and don't leave it on out of habit.
</Callout>

## Which to use

- **Exploring code you don't know** → Plan
- **Normal work** → Normal
- **A long mechanical job on a throwaway branch** → Bypass permissions
