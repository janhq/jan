# Cowork Quickstart

<Steps>

### Open Cowork

Click **Cowork** in the left sidebar.

### Pick a folder

Click **Select folder** and choose the project you want to work on. Everything the agent does is
scoped to this folder - it cannot read or write outside it.

The folder and its git branch show under the input box, so you always know where you are.

```

<Callout type="warning">
  Start on a branch you don't mind changing, or one you can throw away. The agent edits files in
  place.
</Callout>

### Pick a model

Use the model picker next to the input, or type `/models`. Cowork works best with models that are
good at tool calling.

### Describe the task

Write what you want in plain language. You don't need to name files - the agent will search for
them.

```
Add a --dry-run flag to the CLI so it prints the commands it would run
instead of running them. Update the README too.
```

To point at a specific file, type `@` and start typing its path, then Tab to complete it.

### Let it work, or approve as it goes

Cowork starts in **Bypass permissions**: tool calls are auto-approved so the agent can work without
stopping at every step. Confinement does not depend on the prompt - `bash` always runs inside an OS
sandbox (and refuses to run at all if one cannot be established), and file writes stay inside your
project folder either way.

Switch the mode picker to **Normal** if you would rather confirm each change. The agent then stops
before it writes, edits, or runs anything: a write or edit shows the diff first, a shell command
shows the exact command.

- **Allow Once** - just this call
- **Always allow** - stop asking for this for the rest of the session
- **Deny** - refuse it. Closing the dialog or pressing `Esc` also counts as a deny, so the agent
  never proceeds without an explicit allow.

```

Grants live in memory and are never written to disk. What a grant actually covers is in
[Tool permissions](/docs/agent/permissions); to block writes outright rather than confirm them, see
[Run modes](/docs/agent/run-modes).

### Review what changed

Open the **Agent changes** panel to see every write and edit from this session in one place. The
**Progress** panel shows the todo list the agent is working through.

### Keep going

Type your next message any time - even mid-run. It queues and sends when the current turn finishes.

</Steps>

## Useful commands

| Command | What it does |
| --- | --- |
| `/help` | List available commands |
| `/models` | Switch the active model |
| `/goal <condition>` | Keep working until a condition is met |
| `/compact` | Summarize older turns to free up context |
| `/clear` | Clear this session |

## When a run goes wrong

**Stop it.** Cancel ends the current run. Anything already written to disk stays written - cancel
stops the agent, it doesn't undo its work.

**Check the diff.** The Agent changes panel is the fastest way to see what actually happened, and
git will tell you the rest.

**Running out of context?** Watch the token counter near the input. `/compact` summarizes older
turns so you can keep going without starting over - see
[Context & compaction](/docs/agent/context).
