# Cowork window-close durability and permission regression

## Source trace

Verified against the installed `@tauri-apps/api` **2.8.0** (`web-app/node_modules/@tauri-apps/api/window.js`) and locked/cached Rust `tauri` **2.11.5** (`src-tauri/Cargo.lock` and crate source):

1. Rust `src/manager/window.rs::on_window_event` prevents native close when a JS `tauri://close-requested` listener exists, then emits that event.
2. JS `Window.onCloseRequested` awaits the registered handler, then calls `this.destroy()` unless the handler called `preventDefault()`.
3. `destroy()` invokes `plugin:window|destroy`; `allow-close` does not authorize this command. The core window default permission set does not include destroy either (crate `permissions/window/autogenerated/reference.md`).
4. Cowork's handler in `web-app/src/lib/coworkSync.ts` first quiesces active runs through the registry in `hooks/useCoworkRun.ts`. Each `CoworkPage.runRequest` participant aborts its run and waits for its final transcript/wire-history commit and cleanup. Registration survives route unmount; background sessions participate too. New runs and queued restarts are guarded while closing.
5. Only after all participants settle does the handler flush session persistence and pending deletes. `coworkRunner.consumeStep` retains its accumulated partial response when an aborted stream read rejects, so wire history is not silently reduced to the previous completed step. Completed tool results remain in that history.
6. Reviewed durability decision: a quiesce or storage failure is logged and calls `preventDefault()`, preserving the window rather than silently losing unsaved state. The closing guard/cache resets after a prevented close, allowing a later close to retry. This intentionally replaces the previous catch-and-close behavior; no other platform lifecycle handling is changed.

The permission fix adds `core:window:allow-destroy` to `src-tauri/capabilities/default.json`, which is explicitly enabled by `tauri.conf.json`. It applies to the local **main-window caller only**; no remote origin or auxiliary-window capability is added. This built-in command has no target-label scope: Rust `src/window/plugin.rs` resolves the supplied label to a window. Therefore the grant authorizes the main caller to invoke destroy, not exclusively to target itself. Cowork's actual dispatch targets `main`.

## Automated coverage and limits

- `web-app/src/lib/__tests__/coworkClose.test.ts` uses the installed window/event/core JS API and mocked IPC/storage. It verifies that destroy waits for writes/deletes and all active participants, even if one participant rejects; failed closes do not destroy; a later close retries successfully; and dispatch agrees with the active main-window capability.
- `web-app/src/lib/__tests__/coworkSync.test.ts` uses the real persistence adapter with fixture storage and a registered deferred active-run commit. It verifies first-question, partial-response, and completed-tool transcript/wire-history persistence, then reloads those values through the adapter while a different session is viewed.
- `web-app/src/lib/__tests__/coworkRunner.test.ts` uses a real deferred `ReadableStream` that rejects on abort after a completed tool step. It verifies that partial assistant wire history and completed tool output survive without executing the tool twice.

This is **not a Rust ACL emulator, native close test, or evidence of Windows/macOS UI success**. Removing the permission must fail the configuration-alignment assertion even though mocked IPC itself cannot enforce native ACLs.

Run from `web-app`:

```sh
node_modules/.bin/vitest run src/lib/__tests__/coworkClose.test.ts src/lib/__tests__/coworkSync.test.ts src/lib/__tests__/coworkPersistence.test.ts src/lib/__tests__/coworkRunner.test.ts src/hooks/__tests__/useCoworkRun.test.ts
```

Native Windows QA remains required: use an isolated profile, start a first-turn Cowork response, close while it streams, confirm it exits without a destroy-permission denial, then reopen and verify the question, partial response, and completed tool results. Repeat with a background session and delayed delete. Inject a storage failure and confirm the window remains open and a later close retries. macOS retesting is separate; neither platform's native close was exercised by this regression suite.
